# Decision Mirror — Product Requirements Document

> **한 줄 정의**: 증권앱을 여는 순간 사용자의 생체·행동 데이터가 먼저 나타나, 매매 직전 3초의 마찰과 이탈 경로를 만드는 **행동재무 실험 시스템**. 판정을 통보하지 않고, 사용자 자신의 과거를 비춘다.
>
> **사용자 대면명**: 한 번 더 — *시장을 보기 전에, 내 상태를 한 번 더.*
> **프로젝트명**: Decision Mirror (구 No_FOMO)

---

## 1. 문제정의

### 1.1 핵심 문제

개인투자자는 시장 급등·커뮤니티 반응 같은 자극을 받았을 때 생리적 각성과 FOMO가 커져도, 그것이 자신의 투자 판단을 왜곡하고 있다는 사실을 실시간으로 알아차리기 어렵다. 기존 증권 서비스는 시장 상태만 보여줄 뿐 투자자 자신의 상태는 보여주지 않는다.

> **투자자는 시장은 보지만, 흔들리고 있는 자기 자신은 보지 못한다.**

해결 대상은 **정보 부족이 아니라 자기 상태 인식의 부재(state blindness)**다. 고점 물림·몰빵·패닉셀은 이 문제에서 파생된 결과이지 문제 자체가 아니다.

### 1.2 Pain Point

| # | Pain Point | 데이터 근거 |
|---|---|---|
| PP1 | **충동과 판단을 당사자가 구분하기 어렵다.** 사용자는 FOMO를 합리적 투자 판단으로 해석한다 | 빈도 상위 키워드가 '실적·투자·반도체' — 충동 상태에서도 이성의 언어를 사용 |
| PP2 | **기존 도구의 개입 시점이 너무 늦다.** 투자일지·복기는 거래가 끝난 뒤 작동한다 | 트레이딩 저널 4종(Tradervue, TraderSync, Edgewonk, TradeZella) 전부 사후·자기보고 기반 |
| PP3 | **증권앱·커뮤니티는 가속 장치만 있고 감속 장치가 없다** | 급등 알림·실시간 수익률·즉시 주문·수익 인증이 마찰 없이 연결됨 |
| PP4 | **같은 실수를 반복해도 개인화된 학습이 일어나지 않는다** | *"내일 항상 이런 마음을 가진다 아..어제 손절 칠걸.."* (DM-001105) — 패턴을 자각하면서도 반복 |
| PP5 | **텍스트·자가보고만으로는 충동 상태를 포착할 수 없다** | 반복확인 행동 언급 글 16건 중 감정어 없는 글 3건. **자기 상태를 인식하지 못하는 사람은 그것에 대해 글도 쓰지 않는다** |

### 1.3 압축

> 개인투자자는 시장 급변 시 자신의 생리적·행동적 이상 신호를 인식하지 못하고, 충동을 판단으로 합리화한 채 너무 빠르게 의사결정을 내리며, 거래 후에도 결과만 확인할 뿐 자신이 반복하는 충동 패턴은 학습하지 못한다.

### 1.4 포지셔닝

```
                 사후 회고              사전 반영
자기보고 기반    Edgewonk Tiltmeter       —
                 TraderSync

수동 계측        (일부 저널의             ★ Decision Mirror
                 브로커 자동 임포트)
```

> 기존 저널은 당신이 **무엇을 했는지** 알려주고, Decision Mirror는 지금 당신이 **어떤 상태인지** 알려준다.

**H3 기각 시에도 이 좌표는 유지된다**: 웨어러블은 감지 채널의 하나이지 제품 정의가 아니다. 생체신호의 추가 가치가 기각되어도(§7 H3), '사전 × 수동계측(행동)' 사분면 — 인터셉트 시점 기록, 앱 열람 로그, 체결 데이터 — 은 여전히 비어 있는 시장이다.

## 2. 근거 데이터

2026-08-03~04, 4개 채널에서 **5,022건**을 수집해 감정 렉시콘 분석을 수행했다.

| 층위 | 값 |
|---|---|
| 전체 수집 | 5,022행 |
| 분석 모집단(커뮤니티, 뉴스 제외) | 4,576행 |
| 감정 1개 이상 태깅 | **615행 (13.4%)** |
| 태그 발생 횟수 | 704회 |

감정 분포(발생 횟수): 분노·불신 246 > 후회·손실고통 171 > 불안·공포 155 > FOMO·상대적박탈감 70 > 충동·중독 62. 4개 채널 전체에서 동일한 서열.

**추적 가능성**: 모든 행에 고유 ID(`DM-000001`)와 원본 파일·행번호·본문 해시 부여(`research/data/master_dataset.csv`). 인용문은 [verify_quotes.py](../../../../research/verify_quotes.py)로 존재를 자동 대조하며, **각 인용에 claim(무엇을 주장하는가)을 병기**해 맥락 오독을 사람이 검수한다.

### 2.1 관찰된 4가지 사실

| # | 관찰 | 함의 |
|---|---|---|
| 1 | 종목 중심 커뮤니티 3곳은 분노·불신 비중 최고(34~38%), 일반 경제채널은 불안·공포 1위(35%) | 투자 포지션과 밀접한 커뮤니티일수록 분노·불신 표현이 많을 가능성. **보유·손실 여부는 미측정 — 인과 아님** |
| 2 | 감정 표현 비율이 10개 종목 모두 13.4~19.9% 좁은 범위 | 특정 종목에 집중되지 않음 → **투자자·커뮤니티의 상태**를 함께 봐야 함 |
| 3 | 토론방 감정글 평균 공감수 1.44배 (부트스트랩 95% CI [1.23–1.70], 상위 5개 제외 시 1.34배). 일반 채널 0.55배 | 커뮤니티 유형에 따라 감정 표현의 확산 양상이 다름 |
| 4 | 빈도 상위 키워드는 '실적·투자·반도체' (종목명·채널어 제거 전후 15/15 동일) | 키워드 분석으로는 충동 포착 불가 → **행동·생체신호 결합의 필요성** |

### 2.2 방법론적 한계 (명시)

- 텍스트로 관측되는 것은 **사후에 자기 상태를 언어화한 사람들**뿐. 상태 맹시 진행 중인 순간은 원리적으로 텍스트에 없다
- 수집 기간 약 30시간, 목록 상위 편향 — 시간대 기반 주장은 하지 않는다
- 감정 렉시콘은 규칙 기반. **감사 결과 '충동·중독' 태그 샘플의 약 35%가 오탐**(예: "식중독확산", "전기차 올인 전략"이 문자열 매칭)으로 확인되어 렉시콘 정밀화가 진행 중이다(OI-7). §2.1의 관찰 1·2는 감정 총량 기반이라 좁은 범위의 오탐에 상대적으로 강건하나, **감정별 세부 수치는 정밀화 후 갱신될 수 있다**

## 4. User Journey

> 인용 부호가 있는 문장은 실제 수집 데이터이며 DM-ID로 추적된다. 잇는 서술은 `[ASSUMPTION]`.

### UJ-1 — 지하철에서의 3분 (주 저니, daria 실맥락 기반)

**주인공**: daria. 출근길 지하철, 한 손에 폰.

| 순간 | 일어나는 일 |
|---|---|
| 8:40 | 지하철. SNS에서 반도체주 급등 소식을 본다 |
| 8:41 | *"지금이라도 늦지 않았다"*류의 커뮤니티 분위기 (DM-000585 등) — 탑승 압박 |
| 8:42 | 증권앱 아이콘을 누른다 |
| **8:42** | **증권앱 대신 '한 번 더'가 먼저 열린다** (iOS 단축어 자동화) |
| | *지금 심박이 평소보다 높아요.* *어젯밤 수면 5시간 10분.* **한 번 더?** [계속하기] [오늘은 그만] |
| 8:42+15초 | 어느 쪽이든 — **선택 자체가 데이터가 된다** |

**성공 판정**: [계속하기]를 눌러 매수했더라도, 멈춤이 있었고 계획 범위 안이었다면 성공이다(§6.1). 이 제품은 "안 사게 한다"가 아니라 **"알고 사게 한다"**.

**전날 밤 수면 상태의 근거**: `[미확인]` — 수집 텍스트에서 수면과 매매를 직접 연결하는 진술은 발견되지 않았다(초안의 DM-001898 인용은 맥락 오독으로 **철회**됨 — 해당 글의 불면 원인은 재취업 직장 걱정). 이 연결은 자가보고가 아니라 **실측으로만** 확립한다(§5.5 소급 온보딩, `ingest/garmin_ingest.py` → HealthKit/H10 데이터로 교체 예정).

### UJ-2 — 몇 주에 걸쳐 무너지는 사람 (대조군, 제품이 못 잡는 경우)

수집 데이터의 두 목소리: 3년 전 7억을 넣고 반토막을 겪은 40세(*"파이어족 하려다 50살까지는 다시 일해야"*, DM-001898)와, 손실 후 종목을 갈아타며 연쇄 하락을 겪는 50대 중반(*"얼마나 하락했는지 계좌를 못 열어보고 있음"*, DM-001905). **서로 다른 실존 인물이며 합성하지 않는다.**

공통 구조: 개입 지점이 갈아타기 결정(며칠~몇 주 단위)이고, 회피 국면에서는 **증권앱 자체를 열지 않으므로 인터셉트가 발화하지 않는다.** 이 원형은 MVP 범위 밖이며, 사후 회고 리포트(Phase C 이후)의 대상이다.

## 5. 솔루션

### 5.1 아키텍처 — 인터셉트 모델

```
[사용자가 증권앱 아이콘 터치]
        ↓  iOS 단축어 자동화 (순정 기능, 심사 무관)
[한 번 더]가 먼저 열림
        ↓  한 화면:
        L1 사실   "지금 심박이 평소보다 높아요"     ← Polar H10 실시간 (BLE 백그라운드)
                  "어젯밤 수면 5시간 10분"          ← HealthKit
        L2 패턴   "이런 상태에서 최근 5번 중 4번,   ← 자기 이력 통계 (Phase C부터)
                   30분 안에 매수했어요"
        ↓
[계속하기] → 증권앱으로        [오늘은 그만] → 홈으로
```

- **개입 메커니즘의 실증 근거**: one sec(PNAS 2020, n=1,039)이 **정확히 이 경로**(iOS 자동화 인터셉트)로 앱 열기 시도 36% 중단을 측정했다. 우리는 미검증 변형이 아니라 검증된 메커니즘을 쓴다
- **행동 로그는 부산물**: 인터셉트 실행 기록 = 증권앱 열람 로그. 별도 감지 API가 필요 없다
- **노출이 보장된다**: 인터셉트는 증권앱 진입 경로 위에 있으므로, 초안(Glance)의 도달률 문제가 **구조적으로 소멸**한다. H2의 처치 전달도 보장된다(ITT≒처치받은자)

**센서 구성**

| 소스 | 데이터 | 등급 |
|---|---|---|
| Polar H10 (가슴 스트랩, BLE) | RR 간격 실시간 스트림 | **연구급** — HRV 연구에서 ECG 대비 검증된 준거 기기 |
| HealthKit (폴백) | 수면, 안정시 심박 | 소비자급. H10 미착용 시에도 L1 한 줄은 항상 가능 |

H10 착용/미착용 세션의 자연 비교가 **H3 검증**이 된다(§7).

### 5.2 신호 구조 — 실시간과 사후를 분리한다

| 층 | 실시간(인터셉트 화면) | 사후(회고 리포트·모델 연구) |
|---|---|---|
| 시장 자극 | ❌ **표시·트리거 미사용** | ✅ 사용 |
| 생리적 각성 | ✅ 심박·HRV·수면 | ✅ |
| 행동 | ✅ 열람 빈도·시간대 | ✅ + 체결 데이터 |

시장 데이터의 경계를 명확히 한다: **사용자 대면 실시간 화면과 개입 트리거에는 쓰지 않는다**(자본시장법 '시기 판단' 회피, §9.2). 사후 분석과 예측 모델 연구(H1)의 입력으로는 쓴다 — 이는 사용자에게 전달되는 조언이 아니라 내부 검증이다.

### 5.3 개입 문구 — 허용 스펙트럼

| 레벨 | 예시 | 허용 |
|---|---|---|
| **L1 사실** | "지금 심박이 평소보다 14 높아요" / "어젯밤 수면 4시간 50분" | ✅ |
| **L2 자기 이력 패턴** | "지금과 비슷한 상태에서, 당신은 최근 5번 중 4번 30분 안에 매수했어요" | ✅ **상한. Phase C부터** (이력 축적 후) |
| **L3 판정** | "뇌동매매 위험이 높습니다" / "충동 상태입니다" | ❌ **금지** |

L3 금지의 3중 근거: ① 법 — "지금 위험하다"는 시기에 대한 부정적 판단 = 투자자문 해석 여지, 심리 판정은 의료기기 리스크 ② 과학 — 내적 상태는 관측 불가, 판정 모델은 반증 불가 ③ 행동과학 — 숙고·경고 메시지는 효과 0(one sec), 판정은 방어를 유발하며 우리 데이터의 1위 감정(분노·외부귀인)이 앱으로 향한다.

L2는 판정이 아니라 **본인 행동 통계의 조건부 제시**다. "위험합니다"는 반박할 수 있지만 "지난주에도 이랬어요"는 반박이 안 된다.

**정확한 서술**: 이 제품은 "판정하지 않는다"가 아니라 **"판정을 통보하지 않는다"**. 내부적으로는 위험 이벤트를 판정(FR-32)해 트리거로 쓰되, 사용자에게는 판정 결과가 아니라 그 근거 관측치만 제시한다.

### 5.4 개입 프리미티브 (one sec 효과 서열 그대로)

```
명시적 이탈 경로 제시  >  시간 지연 마찰  >>  숙고 유도 메시지 (효과 없음 → 안 씀)
```

1. **관측 사실 노출** — 읽는 시간 자체가 마찰
2. **명시적 이탈 경로** — [오늘은 그만] 버튼을 항상 제시
3. **스누즈** — 사용자가 개입을 일시 중지할 수 있어야 한다. 막으면 자동화를 삭제한다

### 5.5 소급 데이터 온보딩

| 필요한 것 | 확보 경로 | 소요 |
|---|---|---|
| 생리 베이스라인 | HealthKit 과거 데이터 (아이폰·기존 웨어러블 축적분) | 즉시 |
| 과거 거래 기록 | 증권사 거래내역 CSV (체결시각 포함) 수동 업로드 | 즉시 |
| 앱 열람 베이스라인 | 인터셉트 설치 후 신규 수집 | Phase A |
| 상태↔거래 연결 | 신규 수집 | Phase A~B |

```
T-90 ~ T0   과거 데이터 (자연 상태, 소급 확보) ← 순수 통제 기간
T0          온보딩. 과거 요약 1회 노출 ("매매한 날 평균 수면 vs 안 한 날")
T0 ~        Phase A. 인터셉트는 설치하되 화면은 통과만 기록 (silent pass-through)
충족 시     Phase B. 인터셉트 화면 무작위 활성화 (H2)
```

온보딩 1회 노출은 관측자 효과 원칙을 깨지 않는다 — 과거는 확정된 데이터다. 노출 시각을 기록해 이후를 '노출 후'로 분리한다.

### 5.6 Phase 전환 조건

Phase A → B는 데이터 충족 기준: 최소 10거래일 / 인터셉트 발화 20회 이상 / 위험 이벤트 10회 이상 / 오탐 기준선 계산 가능. 초기 적응 구간은 분석 제외.

## 6. 성공 지표

### 6.1 단일 사건 판정표

| 상황 | 판정 |
|---|---|
| 인터셉트 후 계획을 확인하고 계획대로 매수 | **성공** |
| 인터셉트 후 [오늘은 그만] / 보류·수량 축소 | **성공** |
| 인터셉트를 스누즈·해제하고 계획 밖 매수 | 개입 실패 |
| 매수 의도 없는 단순 시세 확인에 과도한 마찰 | 감지 실패 (false positive) |
| 매수 후 손실 발생 | **판단 근거 아님** |

### 6.2 KPI

**① 자기인식 KPI — H4 주가설 측정** *(가장 중요)*
- **자기예측 정확도**: 아침 자가평가("오늘 반응성 거래 위험이 높을 것 같다")와 실제 행동의 일치도(Brier score). 사용 기간에 따른 개선이 H4의 조작적 정의
- **사후 상태 추정 오차**: "방금 심박이 평소보다 높았을까?" 답변 vs 실측. 시간에 따라 감소하는가
- 자기평가–행동 불일치 빈도의 감소

> **자기보고 불신과의 긴장 해소**: 자기보고를 정답지로 쓰지 않고 **예측 대상으로 쓴다.** 정답은 언제나 실측(체결·심박)이며, 자기평가는 채점당하는 쪽이다.

**② 감지 KPI**
- 위험 이벤트(FR-32) 후 30분 내 체결 발생률 (precision) / 실제 체결 중 위험 이벤트 선행 비율 (recall)
- 오탐률: 위험 이벤트 후 당일 체결 없음 비율
- ~~Glance 도달률~~ → **인터셉트 발화율**로 대체: 증권앱 실행 중 인터셉트가 정상 발화한 비율 (자동화 해제·오류 감지)

**③ 개입 KPI**
- [오늘은 그만] 선택률, 인터셉트 → 체결까지 소요 시간 (Phase B 활성/통과 비교)
- 개인 평소 대비 주문 규모 배율, 주문 수정·취소 횟수
- **기존 계획과 불일치한 주문의 비율** — §7.2의 '불일치' 등급만 사용. '불명'은 분모·분자 미포함

> **인식은 단기 성공이고, 의사결정 품질의 지속적 개선이 제품 성공이다.**

## 7. 검증 가설

'상태 맹시'는 전제가 아니라 **반증 가능한 가설**이다. 모델은 숨은 심리가 아니라 **관측 가능한 행동**을 예측한다.

**Primary outcome**: 위험 이벤트 후 30분 내 체결 여부, 거래 반응시간, 개인 평소 대비 주문 규모, 주문 수정·취소 횟수.
**독립 ground truth**: 증권사 거래내역 CSV(체결시각 포함) / 체결통보 메일. 자가보고와 무관하게 존재한다.

| # | 가설 | 위상 | 기각 조건 |
|---|---|---|---|
| **H4** | 사용 후 자기평가와 실제 행동의 일치도가 개선된다 | **주가설** | Brier score 미개선 (§6.2 ①) |
| **H1** | 생체·행동 신호를 더한 모델이 시장 데이터만 쓴 모델보다 30분 내 체결을 더 잘 예측한다 | 주가설 | 예측력 차이 없음 |
| **H3** | H10 착용 세션이 미착용(HealthKit만) 세션보다 감지·개입 성과가 좋다 | 주가설 | 차이 없음 → **웨어러블 제거, 행동-only로 재편** (§1.4 — 제품 좌표는 유지됨) |
| **H2** | 인터셉트 화면 활성 세션이 통과(pass-through) 세션보다 체결까지 시간을 늘리거나 주문 규모를 줄인다 | 보조 | 차이 없음 |

**H2 설계 (v2)**: Phase B에서 인터셉트 발화 시 **화면 표시 / 조용한 통과**를 무작위 배정. 통과 배정 건도 발화·심박은 기록한다. 인터셉트는 진입 경로 위에 있으므로 **처치 전달이 보장**되어 초안의 ITT 희석 문제가 사라진다. 사용자(daria)는 실험 설계에 사전 동의한다.

**실패 조건** (하나라도 나오면 가설 약화·기각): 생체 각성이 체결을 예측 못함 / 행동-only 모델 대비 생체의 추가 가치 없음 / 활성·통과 세션 차이 없음 / 개입이 오히려 확인·불안 증가 / 자기평가가 모델보다 정확 / 개인화 후에도 오탐 지속.

30일 수익률은 보조 분석으로만 둔다.

### 7.2 계획 정보 취급 (3단계 증거 등급)

| 등급 | 정의 |
|---|---|
| 사전 계획 증거 있음 | 자극 이전의 지정가·가격알림·관심종목·메모·이전 날짜 계획 |
| 계획 여부 불명 | 기록 없음. **'계획 밖'이라 부르지 않는다** |
| 기존 계획과 불일치 | 목표가·수량 초과, 다른 종목, 계획보다 급한 진입 |

체크포인트 응답은 정답지가 아니라 자기평가 데이터. 불일치는 판정 없이 기록만 한다.

## 8. 기능 요구사항

### FG-1. 센서·데이터 수집

- **FR-1** 시스템은 Polar H10에서 BLE로 RR 간격을 실시간 수신한다 (iOS `bluetooth-central` 백그라운드 모드)
- **FR-2** 시스템은 RR 간격에서 HRV 지표(RMSSD)를 산출하고, 개인 시간대별 기준선 대비 편차로 저장한다
- **FR-3** 시스템은 HealthKit에서 수면 시간·안정시 심박을 읽는다 (H10 미착용 시 폴백)
- **FR-4** 인터셉트 실행 기록이 증권앱 열람 로그를 겸한다 (시각·요일·직전 열람과의 간격)
- **FR-5** 시스템은 개인 기준선(심박·HRV·열람 빈도)을 시간대별로 산출한다
- **FR-6** 사용자는 증권사 거래내역 CSV(체결시각 포함)를 업로드할 수 있다. `[ASSUMPTION]` 체결통보 메일 자동 파싱은 후순위 — 수동 CSV로 n=1 검증에 충분
- **FR-7** 시스템은 수집 누락 구간을 기록하고 분석에서 제외한다

### FG-1b. 소급 온보딩

- **FR-8** 시스템은 HealthKit 과거 데이터(수면·심박)를 소급 취득한다
- **FR-9** 시스템은 과거 거래일과 생체 데이터를 매칭해 온보딩 요약("매매한 날 vs 안 한 날")을 **1회** 제시한다
- **FR-10** 온보딩 노출 시각을 기록하고 이후 데이터를 '노출 후'로 분리한다

### FG-1c. 위험 이벤트 정의·판정 (내부 판정 — 사용자에게 통보하지 않음)

- **FR-11** 위험 이벤트 = 다음 동시 충족: (a) 심박 또는 HRV가 동일 시간대 개인 기준선 대비 ±Nσ 이탈 (b) 열람 빈도가 직전 T분 기준선 대비 M배 (c) 장중. `[ASSUMPTION]` N=1.5, T=30, M=2.0에서 시작해 오탐률 목표로 조정
- **FR-12** 적격 이벤트 = 직전 이벤트로부터 60분 경과 + 결측 구간 아님 (H2 배정 단위)
- **FR-13** 판정에 쓰인 조건별 충족값을 저장한다 (L2 근거 제시용)
- **FR-14** 활동·수면으로 기록된 구간과 이동 중 가속(걷기·계단)을 판정에서 제외한다 (H10·폰 가속도계)

### FG-2. 인터셉트

- **FR-15** iOS 단축어 자동화로 지정 증권앱 실행 시 '한 번 더'가 먼저 열린다. 설정 가이드를 앱 내 제공한다
- **FR-16** 인터셉트 화면은 L1 사실(현재 심박 편차, 어젯밤 수면)을 표시한다. L2는 Phase C부터(이력 5건 이상 축적 시)
- **FR-17** 화면은 항상 [계속하기]와 [오늘은 그만]을 제시한다. 두 선택 모두 기록된다
- **FR-18** L3 판정 문구는 코드 수준에서 존재하지 않는다 (§5.3)
- **FR-19** 사용자는 스누즈(당일 비활성)할 수 있다. 스누즈도 기록된다
- **FR-20** Phase A에서는 화면 없이 통과하며 발화 기록만 남긴다 / Phase B에서는 무작위로 표시·통과 배정 (H2)
- **FR-21** 자동화 미설정·해제 상태를 감지해 대시보드에 표시한다 (인터셉트 발화율 KPI)

### FG-3. 사후 회고

- **FR-22** 주간 회고는 결과가 아니라 과정을 보여준다: 수면·심박·열람 횟수·인터셉트 반응·선행 시장 맥락(사후에만 시장 데이터 허용)
- **FR-23** 계획 정보를 §7.2의 3단계로 기록한다
- **FR-24** 자기평가와 관측 행동의 불일치를 판정 없이 기록·표시한다
- **FR-25** 아침 자가평가(1탭: 오늘 위험할 것 같다/아니다)를 수집한다 — H4의 예측 대상 데이터
