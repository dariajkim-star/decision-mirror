# Decision Mirror — Product Requirements Document

> **한 줄 정의**: 웨어러블 생체신호와 앱 행동 로그로 개인투자자가 반응성 거래에 취약해진 구간을 감지하고, **판정하지 않고 관측 사실만 비추어** 스스로 멈출 기회를 만드는 행동재무 실험 시스템.
>
> **사용자 대면명**: 한 번 더 — *시장을 보기 전에, 내 상태를 한 번 더.*
> **프로젝트명**: Decision Mirror (구 No_FOMO)

---

## 1. 문제정의

### 1.1 핵심 문제

개인투자자는 시장 급등·커뮤니티 반응 같은 자극을 받았을 때 생리적 각성과 FOMO가 커져도, 그것이 자신의 투자 판단을 왜곡하고 있다는 사실을 실시간으로 알아차리기 어렵다. 기존 증권 서비스는 시장 상태만 보여줄 뿐 투자자 자신의 상태는 보여주지 않는다.

> **투자자는 시장은 보지만, 흔들리고 있는 자기 자신은 보지 못한다.**

해결 대상은 **정보 부족이 아니라 자기 상태 인식의 부재(state blindness)**다. 고점 물림·몰빵·패닉셀은 이 문제에서 파생된 결과이지 문제 자체가 아니다.

### 1.2 Pain Point

| # | Pain Point | 데이터 근거 |
|---|---|---|
| PP1 | **충동과 판단을 당사자가 구분하기 어렵다.** 사용자는 FOMO를 합리적 투자 판단으로 해석한다 | 빈도 상위 키워드가 '실적·투자·반도체' — 충동 상태에서도 이성의 언어를 사용 |
| PP2 | **기존 도구의 개입 시점이 너무 늦다.** 투자일지·복기는 거래가 끝난 뒤 작동한다 | 트레이딩 저널 4종(Tradervue, TraderSync, Edgewonk, TradeZella) 전부 사후·자기보고 기반 |
| PP3 | **증권앱·커뮤니티는 가속 장치만 있고 감속 장치가 없다** | 급등 알림·실시간 수익률·즉시 주문·수익 인증이 마찰 없이 연결됨 |
| PP4 | **같은 실수를 반복해도 개인화된 학습이 일어나지 않는다.** 결과는 기록되지만 결정 과정은 기록되지 않는다 | *"내일 항상 이런 마음을 가진다 아..어제 손절 칠걸.."* (DM-001105) — 패턴을 자각하면서도 반복 |
| PP5 | **텍스트·자가보고만으로는 충동 상태를 포착할 수 없다** | 반복확인 행동을 언급한 글 16건 중 감정어가 없는 글은 3건. **자기 상태를 인식하지 못하는 사람은 그것에 대해 글도 쓰지 않는다** |

### 1.3 압축

> 개인투자자는 시장 급변 시 자신의 생리적·행동적 이상 신호를 인식하지 못하고, 충동을 판단으로 합리화한 채 너무 빠르게 의사결정을 내리며, 거래 후에도 결과만 확인할 뿐 자신이 반복하는 충동 패턴은 학습하지 못한다.

### 1.4 포지셔닝

경쟁 지형을 두 축으로 놓으면 빈 사분면이 드러난다.

```
                 사후 회고          사전 반영
자기보고 기반    Edgewonk Tiltmeter    —
                 TraderSync

수동 계측        (일부 저널의            ★ Decision Mirror
                 브로커 자동 임포트)
```

> 기존 저널은 당신이 **무엇을 했는지** 알려주고, Decision Mirror는 지금 당신이 **어떤 상태인지** 알려준다.

### 2.2 방법론적 한계 (명시)

- 텍스트로 관측되는 것은 **사후에 자기 상태를 언어화할 수 있게 된 사람들**뿐이다. 상태 맹시가 진행 중인 순간은 원리적으로 텍스트에 남지 않는다
- 수집 기간이 약 30시간(2026-08-03 08:32 ~ 08-04 14:41)이고 목록 페이지 상위만 크롤링해 **시간대 분포는 편향**되어 있다. 시간대 기반 주장은 하지 않는다
- 감정 렉시콘은 규칙 기반이며 반어·맥락을 처리하지 못한다

### UJ-1 — 원형 A: 하루 안에서 무너지는 사람

**주인공**: 재현(가명), 40대 초반. 반도체·바이오 종목 위주. 장중 수시로 시세를 확인하며 짧게 사고판다.

| 시각 | 일어나는 일 | 데이터 근거 |
|---|---|---|
| 전날 밤 | 잠들기 전 계좌를 확인한다. 수면이 평소보다 짧다 | DM-001898이 **새벽 02:32**에 *"심란해서 잠도 안 온다"*고 작성 |
| 09:00 | 개장. 보유 종목이 아닌 다른 종목이 급등하기 시작한다 | — |
| 10:06~11:01 | 앱을 반복해서 연다. *"적당히 내리면 사고 적당히 오르면 파는게 수익이 좋아요"*라는 자기 전략이 모니터링을 정당화한다 | DM-002405 |
| 오후 | 원래 하려던 일을 포기하고 차트를 본다. *"등산을 포기하고 그냥 차트를 봤다"* | DM-002124 |
| — | 자기만의 신호 체계를 만들어 진입을 합리화한다. *"내가 어제 우연히 만든 신호... 제발.. 언제나 통하는 수식이기를"* | DM-002124 |
| 결정 | 평소보다 짧은 시간 안에 주문을 낸다 | `[ASSUMPTION]` 결정시간 단축은 미측정 — P1에서 검증 |
| 그 이후 | 체결 직후 다시 확인한다. 감정 진폭이 하루 안에서 크게 흔들린다 | DM-002124 |

**Decision Mirror가 끼어드는 지점**

이 저니에서 제품은 **울리지 않는다.** 재현이 시계를 볼 때(시간 확인, 알림 확인 등 다른 이유로) Glance 화면에 관측 사실이 놓여 있다.

```
오늘 장중 심박   평소보다 +14bpm
금융앱 열람      14회 (개인 평소 5회)
어젯밤 수면      4시간 50분
```

판정 문구는 없다. "충동적입니다", "매수하지 마세요"는 금지어다(§8).

**성공 판정**: 재현이 이 화면을 본 뒤 멈추고, 원래 계획을 확인하고, 계획 범위 안에서 매수했다면 **성공**이다. 매수를 취소했는지는 판정 기준이 아니다.

**실패 모드**: 재현이 그날 시계를 한 번도 보지 않는다. 우리가 잡으려는 순간은 정확히 **시계를 볼 여유가 없을 만큼 몰입한 순간**이다 → **OI-1** (§11).

**주인공**: 정욱(가명), 50대 중반. 2009년부터 투자해 2023년까지 성공 경험만 있었다.

| 국면 | 일어나는 일 | 데이터 근거 |
|---|---|---|
| 진입 | 인플루언서를 통해 종목을 알게 된다. *"배터리 아저씨 덕분에 좋은 기업 알게 되어 좋았지만"* | DM-001898 |
| 고점 | 원금 7억이 12억까지 오른다. *"12억 찍힐 때까진 좋았는데"* | DM-001898 |
| 하락 | 반토막. 손절 대신 다른 종목으로 갈아탄다 → 10분의 1토막 → 또 다른 2차전지 → 또 하락 | DM-001905 |

**Decision Mirror의 한계**

정욱의 개입 지점은 **갈아타기 결정**이며 며칠~몇 주 단위다. 5분 지연 예산 안에 충분히 들어온다. 그러나 회피 국면(*"계좌를 못 열어보고 있음"*)에서는 Glance도 보지 않는다. 이 원형은 MVP 타겟이 아니며, 사후 회고 리포트(Guard Mode 이후)에서 다뤄야 한다.

## 5. 솔루션

### 5.1 단계 구조

```
Decision Mirror (한 번 더)
├─ Phase A  Silent Calibration   수집만. 행동 피드백 없음
├─ Phase B  Mirror Mode          관측 사실 + 중립적 의도 확인. 판정 없음
└─ Phase C  Guard Mode           설명 가능한 위험 신호. 근거 공개형 개입
```

### 5.2 신호 구조 — 실시간과 사후를 분리한다

| 층 | 실시간(Glance) | 사후(회고 리포트) |
|---|---|---|
| 시장 자극 | ❌ **사용하지 않음** | ✅ 사용 |
| 생리적 각성 | ✅ 심박, HRV, 스트레스, 수면 | ✅ |
| 행동 | ✅ 앱 열람 빈도·체류시간·시간대 | ✅ + 체결 데이터 |

**시장 데이터를 실시간 트리거에서 배제**한 것은 자본시장법상 '시기 판단' 해석 여지를 차단하기 위한 설계 결정이다(§9.2).

### 5.3 개입 프리미티브

PNAS 2020(one sec, n=1,039) 연구는 개입을 3요소로 분해해 효과 크기를 측정했다:

```
명시적 이탈 경로 제시  >  시간 지연 마찰  >>  숙고 유도 메시지 (효과 없음)
```

따라서 Decision Mirror의 개입은 **설득하지 않는다.** 유효한 프리미티브는 두 개뿐이다:

1. **관측 사실 노출** (마찰) — 화면을 읽는 데 걸리는 시간 자체가 마찰
2. **명시적 이탈 경로** — "앱 닫기", "10분 뒤 다시 보기" 같은 나가는 길을 항상 제시

### 5.4 소급 데이터 온보딩 — Phase A를 짧게 만든다

Phase A가 필요한 이유는 두 가지인데, 그중 하나는 **이미 존재하는 데이터로 첫날 해결된다.**

| 필요한 것 | 확보 경로 | 소요 |
|---|---|---|
| 생리 베이스라인 (심박·수면·스트레스) | **Garmin Connect 과거 데이터 소급 확보** | 즉시 |
| 과거 거래 라벨 | **체결통보 이메일 소급 파싱** (IMAP, 증권사 발신 주소 필터) | 즉시 |
| 행동 베이스라인 (앱 사용) | 신규 수집 | Phase A |
| 행동↔거래 연결 | 신규 수집 | Phase A |

**타임라인**

```
T-90일 ~ T0    과거 데이터 (자연 상태, 소급 확보)  ← 순수 통제 기간
T0             온보딩. 과거 요약 1회 노출
T0 ~ T+10일    Phase A. 신규 행동 데이터 수집, 피드백 없음
T+10일 ~       Phase B. 즉시/지연 Mirror 무작위 배정
```

온보딩에서 과거 요약을 1회 노출하는 것은 Phase A의 "피드백 없음" 원칙을 깨지 않는다. **관측자 효과가 걱정되는 것은 앞으로 수집할 데이터이며, 과거는 이미 확정되어 변하지 않는다.** 다만 노출이 미래 행동을 바꿀 수 있으므로 **온보딩 시점을 기록하고 이후 데이터를 '노출 후'로 분리**한다. 결과적으로 T-90~T0 구간이 **개입 이전 자연 상태 통제 기간**이 되어 실험 설계상 이득이다.

`[ASSUMPTION]` 가민 과거 데이터 취득은 MVP에서 **Garmin Connect 웹 데이터 내보내기 → 수동 업로드**로 처리한다(Health API 비즈니스 승인 불필요). 확장 시 FIT 파싱 또는 Health API 승인 필요.

### 5.5 Phase 전환 조건

Phase A → B는 기간이 아니라 **데이터 충족 기준**으로 판단한다.

- 최소 10거래일
- 시장 급변 이벤트 20회 이상
- 매수 검토 라벨 10회 이상
- 평상시·고각성 상태 데이터 확보
- 오탐 기준선 계산 가능

초기 며칠은 기기를 의식해 행동이 달라질 수 있으므로 **적응 구간은 분석에서 제외**한다.

## 6. 성공 지표

### 6.1 단일 사건 판정표

| 상황 | 판정 |
|---|---|
| 알림 후 계획을 확인하고 계획대로 매수 | **성공** |
| 알림 후 주문 보류·취소·수량 축소 | **성공** |
| 알림을 무시하고 계획 밖 매수 | 개입 실패 |
| 매수 의도도 없는데 반복 알림 | 감지 실패 (false positive) |
| 매수 후 손실 발생 | **판단 근거 아님** |

수익·손실은 1차 판정 기준이 아니다. 충동매매가 운 좋게 수익을 냈다고 좋은 판단이 되지 않고, 계획된 매매가 손실을 냈다고 나쁜 판단이 되지 않는다.

### 6.2 KPI 2층 분리

**감지 KPI** — 위험 구간을 제대로 찾아냈는가?
- 매수 의도 적중률
- 계획 밖 주문 예측률
- 오탐 알림 수
- 사용자 상태 자가평가와 모델 점수의 보정 정도
- **Glance 도달률** (제품이 실제로 눈에 닿았는가 — Widget 방식의 핵심 리스크 지표)

**개입 KPI** — 감지한 뒤 의사결정 과정이 달라졌는가?
- 체크포인트 완료율
- 의사결정 지연시간
- 보류·취소·수량 축소율
- 계획 이탈률 감소
- 같은 상태에서 반복되는 충동 주문 감소

> **인식은 단기 성공이고, 의사결정 품질의 지속적 개선이 제품 성공이다.**

## 7. 검증 가설

'상태 맹시'는 전제가 아니라 **반증 가능한 가설**로 둔다. 모델은 사용자의 숨은 심리를 판정하지 않고 **관측 가능한 행동**을 예측한다.

**Primary outcome**: 위험 이벤트 이후 일정 시간 안에 실제 거래가 발생하는가 — 30분 내 체결 여부, 거래 반응시간, 개인 평소 대비 주문 규모, 주문 수정·취소 횟수.

**독립 ground truth**: 체결통보 이메일 파싱 / 거래내역 CSV / OCR. 사용자의 "나는 충동이 아니었다"는 응답과 무관하게 존재하는 행동 데이터다.

| # | 가설 | 위상 | 기각 조건 |
|---|---|---|---|
| **H4** | 제품 사용 후 사용자의 자기평가와 실제 후속 행동의 일치도가 개선된다 | **주가설** | 개선 없음 |
| **H1** | 시장·생체·앱 행동 신호가 시장 데이터만 쓴 모델보다 30분 내 체결 여부와 거래 반응시간을 더 잘 예측한다 | 주가설 | 예측력 차이 없음 |
| **H3** | 심박·HRV·스트레스가 시장·앱 행동 데이터만 쓴 모델보다 유의한 추가 설명력을 제공한다 | 주가설 | 추가 성능 없음 → **웨어러블을 제거한다** |
| **H2** | 즉시 Mirror는 지연 Mirror보다 위험 이벤트 이후 거래까지 걸리는 시간을 늘리거나 주문 규모 확대를 줄인다 | 보조 | 차이 없음 |

**H4를 주가설로 두는 이유**는 §11.2 OI-1 참조. 이 제품의 효용은 위험한 그 순간에 개입하는 것이 아니라, **반복 노출을 통해 사용자가 자기 신체 상태를 읽는 능력을 기르는 것**에 있다. 실시간 개입(H2)은 보너스다.

**H2 실험 설계**: Phase B에서 적격 위험 이벤트마다 **즉시 Mirror**와 **지연 Mirror**(장 마감 후 동일 정보 제공)를 무작위 배정한다. 통제군에도 정보를 영원히 숨기지 않고 **즉시 개입만 하지 않는다.** 사용자는 사전에 실험 설계에 동의한다.

**H2 오염 대응**: Glance 도달률이 낮으면 즉시 Mirror로 배정됐으나 실제로는 보지 않은 건이 발생해 처치 효과가 희석된다. 이에 **Glance 열람 로그**를 남기고 두 분석을 병기한다.
- **주분석**: 배정 기준(ITT) — 즉시군 vs 지연군 전체
- **보조분석**: 실제 열람 기준 — 즉시군 중 Glance를 연 건만

### 7.1 프로젝트 실패 조건

다음 중 하나가 나오면 가설은 약화되거나 기각된다.

- 생체 각성이 계획 밖 주문을 예측하지 못함
- 행동 로그만 쓴 모델 대비 생체신호의 추가 가치가 없음
- 개입군과 비개입군의 계획 이탈률 차이가 없음
- 알림 때문에 오히려 금융앱 확인이나 불안이 증가함
- 사용자 자기평가가 모델보다 더 정확함
- 개인화 후에도 오탐이 지속됨

30일 수익률 비교는 **보조 분석으로만** 둔다. 시장·종목·진입 전략의 영향이 커서 "충동 상태였는가"의 정답으로 부적절하다.

### 7.2 계획 정보의 취급

'계획 밖 매수'는 primary label로 쓰지 않는다. 사전 등록은 채택률이 낮고 사후 자가보고는 합리화에 오염되기 때문이다. 대신 **증거 수준 3단계**로 기록한다.

| 등급 | 정의 |
|---|---|
| 사전 계획 증거 있음 | 시장 자극 이전에 지정가 주문·가격 알림·관심종목 등록·목표가 메모·투자 근거 저장·이전 날짜의 매수 계획이 존재 |
| 계획 여부 불명 | 사전 기록도 반대 증거도 없음. **절대 '계획 밖 매수'라 부르지 않는다** |
| 기존 계획과 불일치 | 사전 계획은 있었으나 목표가·수량 초과, 다른 종목, 계획보다 급한 진입 |

체크포인트 응답은 정답지가 아니라 **주관적 자기평가 데이터**다. 자기평가와 관측 행동이 어긋나면 "상태 맹시"로 판정하지 않고 **"불일치가 발생했다"**고만 기록한다.

## 8. 기능 요구사항

### FG-1. 데이터 수집

- **FR-1** 시스템은 Garmin Connect IQ를 통해 실시간 심박(약 1Hz)을 수집한다
- **FR-2** 시스템은 RR 간격(`heartBeatIntervals`)을 수집해 HRV를 산출한다. `[ASSUMPTION]` 기기별 지원 편차가 있어 타깃 기기 실측 검증 필요
- **FR-3** 시스템은 수면 시간·스트레스·Body Battery를 수집한다. 미지원 기기에서는 해당 지표 없이 동작한다
- **FR-4** 시스템은 금융앱 실행 빈도·체류시간·시간대를 기록한다
- **FR-5** 시스템은 개인 기준선(안정시 심박, 평소 HRV, 평소 앱 확인 빈도)을 시간대별로 산출한다
- **FR-6** 시스템은 체결통보 이메일을 파싱해 종목·매수매도·체결시각·가격·수량을 추출한다
- **FR-7** 사용자는 거래내역 CSV를 수동 업로드할 수 있다
- **FR-8** 시스템은 데이터 수집 누락 구간을 기록하고 분석에서 제외한다

### FG-1b. 소급 데이터 온보딩

- **FR-27** 사용자는 Garmin Connect에서 내보낸 과거 생체 데이터를 업로드할 수 있다
- **FR-28** 시스템은 과거 체결통보 이메일을 소급 검색해 거래 이력을 추출한다 (IMAP, 증권사 발신 주소 필터)
- **FR-29** 시스템은 과거 생체 데이터를 시장 캘린더와 매칭해 장중·장외를 구분한다
- **FR-30** 시스템은 온보딩 시 과거 요약을 **1회** 제시한다. 이후 Phase A 동안에는 어떤 행동 수치도 표시하지 않는다
- **FR-31** 시스템은 온보딩 노출 시각을 기록해 이후 데이터를 '노출 후'로 분리 표시한다

### FG-2. Phase A — Silent Calibration

- **FR-9** 시스템은 Phase A 동안 어떤 행동 수치도 사용자에게 표시하지 않는다 (관측자 효과 방지)
- **FR-10** 시스템은 운영 정보만 표시한다: 데이터 연결 여부, 수집 누락, 기준선 계산 진행 상태, 센서 배터리·동기화
- **FR-11** 시스템은 §5.4 충족 기준을 만족하면 Phase B 전환 가능 상태를 사용자에게 알린다
- **FR-12** 시스템은 초기 적응 구간을 분석 대상에서 제외한다

### FG-3. Phase B — Mirror Mode

- **FR-13** 시스템은 Garmin Widget/Glance에 관측 사실을 표시한다. 푸시 알림이 아니라 사용자가 볼 때 노출되는 방식이다
- **FR-14** Glance는 개인 기준선 대비 편차로 표기한다 (절대 임계치 금지 — §9.3)
- **FR-15** 시스템은 위험 이벤트 시 중립적 의도 확인 질문을 제시한다. 예: *"오늘 이전부터 매수 계획이 있었나요?"*
- **FR-16** 모든 개입 화면은 명시적 이탈 경로를 함께 제시한다 ("앱 닫기", "10분 뒤 다시 보기")
- **FR-17** 시스템은 적격 위험 이벤트를 즉시 Mirror / 지연 Mirror로 무작위 배정한다 (H2 검증)
- **FR-17a** 시스템은 **Glance 열람 여부와 시각을 로깅**한다. ITT 분석과 처치받은자 분석을 모두 산출하기 위한 필수 데이터다
- **FR-18** 지연 Mirror 배정 건은 장 마감 후 동일 정보를 제공한다
- **FR-19** 사용자는 개입을 일시 중지(스누즈)할 수 있다
- **FR-20** 개입 강도·주기 설정에서 **강화는 즉시 반영, 완화는 24시간 지연**된다 (비대칭 설계)

### FG-4. Phase C — Guard Mode

- **FR-21** 시스템은 위험 신호의 **근거를 공개**한다. 예: *"평소와 다른 신호가 셋 겹쳤습니다 — ① 장중 심박 +16bpm ② 평소보다 높은 앱 확인 빈도 ③ 수면 4시간 50분"*
- **FR-22** 시스템은 점수만 제시하지 않는다. `FOMO 87%` 형태의 불투명한 판정 금지

### FG-5. 사후 회고

- **FR-23** 시스템은 주간 회고에서 결과가 아니라 **과정**을 보여준다: 수면, 심박, 반복 확인 횟수, 결정시간, 선행 시장 자극
- **FR-24** 회고에서는 시장 데이터를 사용할 수 있다 (실시간 트리거와 달리)
- **FR-25** 시스템은 계획 정보를 §7.2의 3단계로 기록한다
- **FR-26** 시스템은 자기평가와 관측 행동의 불일치를 판정 없이 기록·표시한다

## 9. 비기능 요구사항

### 9.1 플랫폼 제약 (확인된 사실)

| 제약 | 영향 | 대응 |
|---|---|---|
| `Toybox.Attention`(진동)이 백그라운드에서 사용 불가 | 감지 즉시 진동 불가 | Widget/Glance 수동 노출 방식 채택 |
| 백그라운드 이벤트 최소 5분 간격 | 초 단위 반응 불가 | **개입 지연 예산을 5분 이상으로 설계** |
| 시계 홈 화면에 서드파티 상시 표출 불가 | 수동적 노출 경로 제한 | Glance 진입 유도 설계 필요 → OI-1 |
| Health API는 비즈니스 용도 한정, 승인 필요 | 개인 개발자 접근 제약 | Connect IQ 온디바이스 우선 |

- **NFR-1** 개입 지연 예산은 위험 구간 진입 후 5분 이내 인지로 정의한다. "주문 직전 실시간 차단"은 목표가 아니다
- **NFR-2** 스트레스·Body Battery 미지원 기기에서도 심박·행동 데이터만으로 동작해야 한다

### 9.2 규제 — 투자자문업 회피

자본시장법상 **투자판단** = 금융투자상품의 종류·종목·취득처분·방법·수량·가격 및 **시기**에 관한 판단. Decision Mirror는 이 중 어느 것도 제공하지 않는 위치에 선다.

- **NFR-3** 모든 사용자 대면 문구는 **1인칭 사실 서술 + 사용자 자신의 과거 데이터 기준**이어야 한다
- **NFR-4** 3인칭 권고형·명령형 문장을 프로덕트 전체에서 금지한다
- **NFR-5** 시장 데이터는 실시간 개입 트리거에 사용하지 않는다

**금지 문구** (즉시 자문업 영역):
- ❌ "지금은 매수하지 마세요" / "잠시 매도를 미루세요" → 시기 판단
- ❌ "이 종목은 변동성이 높으니 비중을 줄이세요" → 종목·수량
- ❌ 시장 데이터를 결합해 사용자 개별 상황에 맞춰 "현재 시장이 과열이니…"

`[NOTE FOR PM]` 런칭 전 금융위 유권해석 신청 + 변호사 검토 필요. 본 문서는 법률 자문이 아니다.

### 9.3 규제 — 의료기기 회피

식약처 「의료기기와 개인용 건강관리(웰니스) 제품 판단기준」상 웰니스 제품에 해당할 가능성이 높다. 가이드라인이 "스트레스 관리·수면 관리 소프트웨어"와 "스트레스 정도를 알기 위해 심박수 변화 등을 자가 측정하는 제품"을 웰니스 예시로 직접 수록하고 있다.

- **NFR-6** 질환명 언급 또는 스크리닝 주장을 금지한다 (불안장애·우울증·충동조절장애·도박중독 등)
- **NFR-7** 위급 상황 탐지 기능(부정맥 등)을 포함하지 않는다
- **NFR-8** 진단·치료 효과를 표방하지 않는다
- **NFR-9** HRV는 **절대 임계치가 아니라 개인 베이스라인 대비 편차**로만 해석한다. 문헌상 "HRV 낮음 = 나쁜 결정"이라는 단순 매핑은 지지되지 않는다

### 9.4 개인정보

- **NFR-10** 생체 데이터는 다른 개인정보와 **명확히 구분되는 별도 동의**를 받는다
- **NFR-11** 원시 생체 데이터는 서버로 전송하지 않는다. 온디바이스 처리를 우선한다
- **NFR-12** 증권 계좌·체결 데이터 연동 시 신용정보법을 별도 검토한다

`[NOTE FOR PM]` 생체 데이터를 "충동 취약 상태"로 해석하고 금융거래 행동과 결합하는 프로파일링이 민감정보 처리로 해석될 여지가 있다. 개인정보보호위원회 유권해석 권장.

## 10. 설계 원칙 및 금지 사항

### 10.1 게이미피케이션 전면 금지

행동·생체 지표 화면에서 다음을 금지한다.

스트릭 · 배지 · 랭킹 · 다른 사용자와 비교 · 총점·등급 · 목표 달성률 · 연속 성공일 · 빨강/초록 합격·실패 표시 · "좋아졌습니다" / "나빠졌습니다" · "오늘은 잘 참았습니다" · 숫자를 보러 다시 들어오게 만드는 푸시 · **실시간 행동 카운터의 홈 화면 상시 노출**

> 금융앱 확인 강박을 Decision Mirror 확인 강박으로 바꾸면 완벽한 자책골이다.

**허용**: 데이터 연결 여부, 수집 누락, 기준선 계산 진행 상태, 센서 배터리·동기화 — **운영 정보만**.

허용 예: `기준선 계산용 데이터 8일 수집`
금지 예: `10일 목표 중 8일 달성! 이틀만 더!`

### 10.2 화면 원칙

- 실시간 점수판 없음
- 기본 화면은 주간 또는 이벤트 단위
- 절대 점수보다 관측 사실 표시
- 목표선·경쟁 기준 없음
- 원시 수치는 사용자가 요청할 때만 상세 조회
- 평가가 아니라 맥락 설명

> 화요일 오후 시장 변동성이 높아진 구간에서 평소보다 금융앱을 자주 열었고, 심박수도 개인 기준 범위를 벗어났습니다.

여기까지 보여주고 "좋았다·나빴다"는 사용자가 판단한다.

## 11. 범위 밖 · 오픈 이슈

### 11.1 이 프로젝트가 해결하지 않는 것

- 종목 예측 / 적정 매수가 추천 / 투자자문
- 모든 고점 매수 방지
- 감정의 의학적 진단
- 수익률 보장
- **사용자의 숨은 심리("진짜 충동")를 판정하는 것**

### 11.2 오픈 이슈

#### OI-1 처리 — 해결이 아니라 회피다

**문제는 실재한다.** Glance는 사용자가 볼 때만 작동하고, 몰입도가 높을수록 볼 확률은 떨어진다. 이 역상관은 Widget 방식의 구조적 성질이며 기술로 없앨 수 없다(백그라운드 진동 불가 — §9.1).

**대응은 제품 정의를 바꾸는 것이다.** "그 순간에 개입한다"를 버리고, **반복 노출로 자기 상태를 읽는 능력을 기른다**를 제품의 중심에 놓는다. 거울의 효용은 거울 앞에 선 그 순간이 아니라, 매일 봐서 자기 얼굴을 알게 되는 데 있다. 이에 따라 **H4를 주가설로 승격**하고 H2를 보조로 내렸다(§7).

**대가를 명시한다.**
- 검증 기간이 이벤트 단위 몇 주에서 **2~3개월**로 늘어난다
- OI-3(이벤트 수 부족)의 압력이 커진다
- Glance 도달률 자체를 감지 KPI로 계속 측정해야 한다(§6.2)

> 이것은 문제를 푼 것이 아니라 **측정 대상을 바꿔 우회한 것**이다. 실시간 개입의 효과를 보고 싶다면 폰 앱 하이브리드로 아키텍처를 되돌려야 한다.
